# Практична робота 2

Гілка викладача: `practice-02-starter` у репозиторії
<https://github.com/serhii-ch-eu/digital-dean-api-starter/tree/practice-02-starter>.

Це студентська заготовка для симетричного шифрування службових приміток у тому самому API «Цифровий деканат». Вона додає нові файли, але не замінює вашу завершену практичну роботу 1 і не містить готового розв’язку роботи 2.

## Приєднання до власної роботи

Відкрийте наявний локальний клон свого форку. `origin` має вказувати на ваш GitHub, а `upstream` — на репозиторій викладача. Якщо локального клону немає, клонуйте власний форк, у якому вже опубліковано виконану роботу 1 та тег `practice-01`; не створюйте новий непов’язаний репозиторій.

Якщо `upstream` відсутній, один раз додайте його:

```bash
git remote add upstream https://github.com/serhii-ch-eu/digital-dean-api-starter.git
```

Працюйте з чистим робочим деревом. Не продовжуйте після помилки команди.

```bash
git status --short
git remote -v
git fetch origin --tags
git switch -c practice-02 refs/tags/practice-01
python -m pytest
git fetch upstream
git merge --no-ff upstream/practice-02-starter -m "Import practice 2 scaffold"
git merge-base --is-ancestor refs/tags/practice-01 HEAD
git merge-base --is-ancestor upstream/practice-02-starter HEAD
git tag practice-02-base
python -m pytest tests/test_health.py
```

Якщо `practice-02` уже існує, перейдіть до неї через `git switch practice-02`, перевірте її історію й не повторюйте створення. Якщо тег `practice-02-base` уже існує, перевірте його та не перезаписуйте. Створюйте цей тег відразу після успішного злиття, до власних змін роботи 2.

Гілка заготовки додає файли, не змінюючи файлів `main`. У разі конфлікту з вашими вже створеними файлами узгодьте вміст вручну, зберігаючи моделі, маршрути, тести й індивідуальний варіант роботи 1. Не застосовуйте примусове скидання, заміну всього `app` або злиття непов’язаних історій. Завершіть конфлікт, виконайте тести й лише після цього створюйте базовий тег.

## Склад заготовки

- `app/security` — сигнатури криптографічних адаптерів, контексту й лічильника; генератор матеріалу ключа;
- `app/schemas/secure_note.py` — моделі приміток із невиконаною перевіркою тексту;
- `app/repositories/secure_note_repository.py` — структура зашифрованого запису і каркас сховища;
- `app/api/secure_notes.py`, `app/api/crypto_lab.py` — каркаси нових маршрутизаторів;
- `benchmarks/crypto_benchmark.py` — параметри досліду, аргументи запуску й невиконані функції;
- `tests/test_crypto.py`, `tests/test_secure_notes.py` — початкові перевірки приймання;
- `postman/digital-dean-practice-02.postman_collection.json` — послідовність клієнтських запитів;
- `docs/practice-02-report-template.md` — структура звіту;
- `results/practice-02/README.md` — вимоги до файлів результатів;
- `requirements-practice-02.txt` — версії двох додаткових бібліотек.

Позначки `TODO` визначають зміни студента. Невиконані функції піднімають `NotImplementedError`, а нові маршрути ще не підключені до застосунку. Нові тести до реалізації мають падати; їх не можна видаляти, пропускати або послаблювати для одержання успішного результату. Старі тести роботи 1 повинні залишатися успішними. Успішний `/health` не означає завершення роботи 2.

## Залежності та виконання

Додайте до наявного списку залежностей у `pyproject.toml`:

```text
cryptography==48.0.1
pycryptodome==3.24.0
```

Не створюйте другий розділ `[project]` і не вилучайте залежності роботи 1. Встановлення виконують у своєму віртуальному середовищі через `python -m pip install -e ".[dev]"`. Зафіксовані версії є навчальним профілем, а не твердженням про найновіші версії.

Реалізуйте шість комбінацій: AES-128-GCM, AES-256-GCM і ChaCha20-Poly1305 у `cryptography` та `PyCryptodome`. Для визначеного профілю одноразове значення становить 12 байтів, тег — 16 байтів. Базовий API використовує AES-256-GCM у `cryptography`; це навчальний контракт, а не універсально найкращий вибір.

Підключіть маршрутизатори в наявному `app/main.py`, встановіть версію застосунку й пакета `0.2.0`. Реалізуйте контракт, перевірки підміни, методику вимірювань та індивідуальний варіант із документа практичної роботи. Ключ приміток і його лічильник створюються один раз на процес, не на запит. Очищення приміток не скидає лічильника чинного ключа. Ключі для досліду незалежні від ключа API.

```bash
python -m uvicorn app.main:app --reload --host 127.0.0.1
python -m pytest
python -m benchmarks.crypto_benchmark --output-dir results/practice-02
```

До реалізації остання команда завершується повідомленням про невиконаний модуль і не створює вигаданих числових результатів. Після реалізації API читає `report.json` за фіксованим налаштованим шляхом, але не запускає дорогий дослід на HTTP-запит.

## Коміти та подання

Зробіть щонайменше чотири власні змістовні коміти після `practice-02-base`: адаптери й залежності, інтеграція API, перевірки, дослід з варіантом і документацією. Коміти викладача і коміт приєднання заготовки не входять до цього мінімуму.

```bash
python -m pytest
git status --short
git log --no-merges --oneline refs/tags/practice-02-base..HEAD
git push -u origin practice-02
git push origin refs/tags/practice-02-base
git tag -a practice-02 -m "Практична робота 2 завершена"
git push origin refs/tags/practice-02
git ls-remote --tags origin "refs/tags/practice-02*"
```

Подайте посилання на свою гілку й обидва теги, список власних комітів, код, повні тести, колекцію Postman, `raw.csv`, `report.json`, графіки та звіт. Не надсилайте зміни до `upstream` і не переміщуйте теги примусово.

Використовуйте лише вигадані записи. Не записуйте ключі у файли, історію Git, запити чи результати. Немає готових ключів, приміток або числових вимірювань у заготовці. Навчальний локальний API без автентифікації не можна відкривати для реальних освітніх даних.
